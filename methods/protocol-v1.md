# Bounded pilot protocol v1

Frozen before workload calls. CL1–CL3 remain exactly as recorded in README.

Question: lifetime value of acquired source support for a small dispatch memory,
versus all-exposure repair, correction-time reconstruction, and whole rebuilding.
This is a synthetic feasibility study, not a reproduction of the cited systems.

## Workload and split

Pilot seed 101; prospective fresh seeds 211, 307, 419. Eight source records,
eight typed memory fields, two cumulative authoritative corrections. Fields
include indirect arithmetic, disjunctive independent escort support, unchanged
obligations, and a nonauthoritative distracting suggestion. All sources are
visible at writing: runtime exposure is the full archive for every field.
Model-generated links are separate claims. Generator truth scores field values
and semantic candidate-support recall; no truth or gold links enter a request.
Semantic support labels include both independent escort sources initially;
this measures candidate support coverage, not a unique causal explanation.
The model writes the starting memory; all arms fork the same actual result.
No excluding failed initial writes or failed acquisition. If acquisition fails,
inspect omissions, parsing, redundant support and arithmetic separately before
interpreting correction failures. Any revised method requires new held-out seeds.

## Arms and access

Selective: acquire source links after the ordinary write (an extra paid call),
select fields by links to the replaced source, recompute selected fields and pay
to maintain their links. This measures acquisition alongside writing, not a
joint-output optimization. Exposure: select all fields because all records were
visible. Reconstruction: a model scans original and current archives and current
memory on each correction and selects all potentially affected keys.
Rebuild: regenerate every field without old memory. Every repair has the same
original archive, authoritative replacements, and current archive. Every arm
uses the same instruction to check arithmetic and preserve obligations.
No evaluator correctness feedback. Deterministic schema checks are applied
uniformly, recorded as failures, and do not silently regenerate outputs.

Every arm then gets two unseen quantities in a fresh model call with memory and
full source archive and an explicit source audit instruction. This is a competent
common query-time audit; it may rescue behavior even when persistent state is
wrong, so persistent-state correctness is separately mandatory. No bare deletion
or abstention can pass. Fresh tasks are new inputs from the same template, not
held-out domains. Flat source-to-field dependency claims cover indirect premises;
this pilot does not establish performance on multi-stage memory graphs.

## Metrics, costs and stopping

Primary descriptive outcome: all eight persistent fields correct AND both new
orders completely correct, including all unaffected obligations. Report state,
affected, unaffected and fresh outcomes separately. Exact typed values, document
lists compared without order; no model judge. Acquisition precision/recall is
scored before interpreting failures. Report all episodes with no outcome-based
selection. One model, temperature zero; responses pin resolved GGUF path and
server fingerprint, but numerical determinism is not assumed.

Retain full requests/responses, usage, elapsed time, model identity, source hashes,
generated fixtures and script/repository revision. Deployment costs count ordinary
writing, acquisition, reconstruction, repair, maintenance and audited use. Initial
writes are shared experimentally but charged once per arm deployment; never sum
per-event initial-inclusive costs to estimate a lifetime. Research costs are the
actual unique calls plus capability testing and literature preparation. Source
storage is common; lineage serialized bytes are additional descriptive storage.
Server token usage and timings are available; energy and total accelerator
compute are not measured. Python bookkeeping/check cost is part of run wall time,
not a claimed zero compute cost. Run calls sequentially and make no latency
ranking claims because other server use is uncontrolled. Do not start heavy
training, throughput or timing comparisons without hardware coordination.

Complete the pilot, inspect failures, then run unchanged fresh seeds if feasible.
Stop this phase on explanatory results or an evidenced resource constraint.
No significance/generalization claim from three fresh template instances.
Frequency break-even can only be labeled an algebraic scenario under stationary
marginal costs, never empirical long-horizon validation from two events.
