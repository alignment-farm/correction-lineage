# Independent correction-lineage study

Read [README.md](README.md). This repository owns workload selection, methods,
protocols, execution, diagnosis and publication. Construct-2 owns root theory
and synthesis. In an assigned fresh session, proceed autonomously within the
bounded question; repository preparation itself launches no model runs.

- Begin with the closest public methods. Workload discovery and bounded pilot
  development are authorized. Establish acquired, usable dependency information
  before interpreting correction failure; no selective-lineage advantage is required.
- Distinguish runtime exposure records, acquired semantic support claims and
  evaluator truth. Do not supply gold dependencies as learned lineage. Begin with
  known authoritative corrections; separate fault detection from repair.
- Give alternatives the same source archive, current evidence and checking access.
  Develop conservative provenance and competent reconstruction/audit alternatives.
  Measure complete correction, unaffected obligations and later fresh tasks.
- Count ordinary write and checking costs as well as repair, use and failures.
  Separate experimental search from deployment. Do not equate deleting stale
  items, erasing all memory or abstaining with complete task success.
- Diagnose failed acquisition to distinguish plausible causes within available
  resources. Preserve failures and original expectations. Assess claims developed
  through diagnosis on fresh material; never select on final evaluation outcomes.
- Pin paper versions, code, datasets and artifacts. Distinguish inspected methods,
  author-reported results, local observations and inference. For arXiv metadata
  use the query API, cache responses and use a descriptive User-Agent; keep
  API/OAI requests on one connection at least three seconds apart across clients
  under control and honor Retry-After.
- Keep evidence and reproduction instructions local and identifiable by Git
  revision. Close on explanatory progress, a demonstrated limitation or a concrete
  resource constraint; publication acceptance and broader question closure differ.
- Do not modify the root or sibling studies. Copy needed artifacts with provenance.
  Coordinate shared hardware when heavy jobs or timing comparisons interfere;
  independent scientific work need not wait for another study's results.

  Keep credentials, environments, caches and model downloads out of Git; retain
  evidence needed for claims. Use controlled task environments. Explain a material
  expansion beyond these resources before undertaking it.
